# 09 — Internacionalização

Padrão oficial do Flutter: **ARB + `gen_l10n`**. Nenhuma string visível ao usuário é
escrita direto no código.

```yaml
# pubspec.yaml
dependencies:
  flutter_localizations: {sdk: flutter}
  intl: any
flutter:
  generate: true      # liga a geração de AppLocalizations
```

```yaml
# l10n.yaml (raiz)
arb-dir: lib/l10n
template-arb-file: app_pt.arb
output-localization-file: app_localizations.dart
untranslated-messages-file: lib/l10n/error.txt
```

```dart
MaterialApp(
  localizationsDelegates: AppLocalizations.localizationsDelegates,
  supportedLocales: AppLocalizations.supportedLocales,
)
```

## Regra única de acesso

> - **Dentro de um `build` (ou com `context` à mão):** `AppLocalizations.of(context)!`
> - **Fora de widget** (cubit, model, util, validator, interceptor): `globals.l10n!`
>
> **Nunca** escreva `AppLocalizations.of(AppRoutes.navigatorKey.currentContext!)` à
> mão — é o que `globals.l10n` já faz, e repetir espalha o acoplamento ao
> `navigatorKey` por todo o código.

Se preferir menos verbosidade no `build`, crie **uma** extension e use só ela:
`extension L10nX on BuildContext { AppLocalizations get l10n => AppLocalizations.of(this)!; }`.
Adote uma forma e mantenha em todo o app.

## Constante que depende de tradução tem que ser função

Campo `static` é resolvido uma vez, no primeiro acesso: trocar o idioma em runtime não
atualiza, e se for lido antes do primeiro frame, `l10n` é `null` e explode.

```dart
// ❌  static List<TabBarModel> homeTabBarItems = [ TabBarModel(text: globals.l10n!.…) ];

// ✅ função, reavaliada a cada chamada
class AppConstants {
  static List<TabBarModel> homeTabBarItems(BuildContext context) => [
        TabBarModel(text: AppLocalizations.of(context)!.operationalDashboardTabTitle),
      ];

  static List<DropdownModel> buyTypeFilter(BuildContext context) => BuyType.values
      .map((e) => DropdownModel(key: AppUtils.buyTypeToString(e), value: e))
      .toList();
}
```

**Regra:** nada em `settings/` que dependa de `l10n` ou de `MediaQuery` pode ser campo
`static` — tem que ser função ou getter. Vale para `AppConstants` e `AppFonts`
([08](08-ui-design-system.md)).

## Onde tradução aparece além da UI

Mensagens de erro (`ErrorModel`, `AppErrorCodes.messageFor`) · validadores
(`AppValidators`) · enum → texto (`AppUtils.xTypeToString`) · listas de opções
(`AppConstants.xxx(context)`).

Números, moeda e data passam por `AppUtils` com o locale ativo, para que trocar o
locale mude símbolo e separador automaticamente:

```dart
static String numToMoney(num value, {bool withCents = false}) =>
    NumberFormat.simpleCurrency(
      locale: globals.l10n!.localeName,
      decimalDigits: withCents ? 2 : 0,
    ).format(withCents ? value : value.truncate());
```

## Regras de chave

- `camelCase` descritiva, com sufixo de papel: `emailLabel`, `emailHint`,
  `emailError`, `loginScreenTitle`, `signInButton`.
- O template (`app_pt.arb`) é a fonte da verdade; os outros só traduzem.
- Nunca concatene frases traduzidas — use placeholders:
  ```json
  "goalOfMonth": "Meta de {month}",
  "@goalOfMonth": { "placeholders": { "month": { "type": "String" } } }
  ```
- Todo código em `AppErrorCodes` tem chave correspondente no ARB.
- Depois de mexer no ARB, rode o build e cheque `lib/l10n/error.txt` — ele lista as
  chaves ainda não traduzidas.
